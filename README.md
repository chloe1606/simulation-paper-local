# Airline Crew Resilience Simulation

Discrete-event simulation for airline crew scheduling resilience under delays and sickness disruptions.

The current pipeline uses a max-coverage ILP to build crew assignments before running the SimPy simulation.

## End-to-End Flow

`run_simulation.py` is the main script for a full run:

1. Generate input workbook tables (`utility/flight_data_generator.py`)
2. Build `crew_assignment_fact` using ILP max coverage (`simulation/optimize_roster.py`)
3. Run delay + sickness simulation (`simulation/engine.py`)
4. Validate post-simulation constraints (`utility/validation.py`)
5. Compute summary metrics (`utility/metrics.py`)

## Data Model

The simulation reads/writes an Excel workbook in `input/airline_inputs.xlsx` with these sheets:

- `flight_schedule_fact`
- `duty_fact`
- `sectors_dim`
- `aircraft_dim`
- `crew_dim`
- `crew_assignment_fact`

`crew_assignment_fact` is generated by the optimizer and then consumed by the simulation engine.

## Core Components

### 1) Flight and Crew Data Generation

`utility/flight_data_generator.py`

- Generates 28-day short-haul schedule from LHR
- Uses 5 aircraft and configurable active/standby crew counts
- Exports DFS-style tables to `input/airline_inputs.xlsx`

### 2) ILP Crew Assignment

`simulation/optimize_roster.py`

- Objective: maximize number of fully covered duties
- Decision variables:
    - `x[c, d]` binary crew-to-duty assignment
    - `covered[d]` binary duty coverage indicator
- Key constraints:
    - exactly 0 or 2 pilots per duty
    - incompatible duty pair rest conflicts
    - 28-day duty-time cap per crew
    - optional standby protection

Note: the 28-day duty limit is applied in minutes in the optimizer (hours from config converted to minutes).

### 3) Simulation Engine

`simulation/engine.py`

- SimPy event simulation over scheduled departures
- Random delay process with connection propagation
- Daily sickness process with optional fatigue-adjusted probability
- Replacement search via `simulation/crew_ops.py`
- Runtime cancellation checks (duty overrun, curfew, crew shortfall)

### 4) Validation

`utility/validation.py`

Checks include:

- max duty period
- rolling 7/14/28-day duty-hour caps
- minimum rest between duties
- minimum connection time

### 5) Metrics

`utility/metrics.py`

Computes output metrics such as:

- flight completion and cancellations
- delay totals and propagation factor
- duty coverage and crew utilization
- block hours and reassignment counts

## Configuration

Defaults are in `simulation/config.py`:

- absence and delay probabilities
- duty and rest limits
- pre/post duty buffers
- curfew and delay thresholds
- file paths for input/output workbook

Key default values:

| Parameter | Default | Description |
| --- | --- | --- |
| `absence_probability` | `0.02` | Base daily sickness probability per crew member |
| `absence_probability_equation` | `False` | Use flat absence probability instead of fatigue-adjusted equation |
| `max_duty_hours` | `12` | Maximum duty window hours |
| `min_rest_hours` | `12` | Minimum rest hours between duty periods |
| `min_connection_minutes` | `45` | Minimum connection/turnaround minutes |
| `pre_duty_minutes` | `60` | Pre-flight reporting buffer before first leg |
| `post_duty_minutes` | `30` | Post-flight/debrief buffer after last leg |
| `pilots_per_duty` | `2` | Required crew count per covered duty |
| `max_delay_minutes` | `300` | Excessive delay auto-cancellation threshold |
| `curfew_hour` | `23` | Curfew hour component |
| `curfew_minute` | `0` | Curfew minute component |
| `standby_notification_minutes` | `90` | Minimum notice required for standby call-out |
| `delay_probability` | `0.2` | Probability a flight receives a random delay |
| `delay_mean_minutes` | `45.0` | Mean of random delay distribution (minutes) |
| `delay_std_minutes` | `15.0` | Standard deviation of random delay distribution |
| `delay_min_minutes` | `15` | Lower clamp on sampled delays |
| `delay_max_minutes` | `60` | Upper clamp on sampled delays |
| `delay_step_minutes` | `5` | Delay rounding step size |
| `sick_duration_options` | `(24, 48)` | Possible sickness durations in hours |
| `duty_days_on` | `6` | Consecutive duty days before rest block |
| `duty_days_off` | `3` | Consecutive rest days after duty block |
| `max_duty_hours_7D` | `60` | Rolling 7-day duty-hour cap |
| `max_duty_hours_14D` | `110` | Rolling 14-day duty-hour cap |
| `max_duty_hours_28D` | `190` | Rolling 28-day duty-hour cap |
| `seed` | `None` | RNG seed for reproducibility when set |
| `debug` | `True` | Enables debug-mode behavior/logging paths |
| `fatigue_consecutive_threshold` | `3` | Consecutive-day threshold for fatigue penalty |
| `fatigue_consecutive_weight` | `0.003` | Probability increment per extra consecutive duty day |
| `fatigue_rest_deficit_threshold` | `8` | Expected days off in rolling 28-day window |
| `fatigue_rest_deficit_weight` | `0.001` | Probability increment per missing day off |
| `fatigue_max_probability` | `0.05` | Upper cap on fatigue-adjusted absence probability |
| `input_file` | `input/airline_inputs.xlsx` | Input workbook path |
| `output_file` | `output/post_simulation_roster.xlsx` | Simulation output workbook path |

## Setup

### Python

Use Python 3.11+ (project currently runs in a local venv).

### Install packages

```powershell
pip install pandas simpy openpyxl pulp
```

## How To Run

### Full single run

```powershell
python run_simulation.py
```

This generates/updates:

- `input/airline_inputs.xlsx`
- `output/post_simulation_roster.xlsx`

and prints validation plus metrics to console.

### Parameter sweep

```powershell
python new_run_sweep.py
```

Produces sweep outputs:

- `crew_resilience_seed_sweep_v11_2.csv`
- `crew_resilience_seed_sweep_v11_2.xlsx`

### Coverage baseline study

```powershell
python seed_data.py
```

Produces:

- `baseline_coverage_runs.xlsx`
- `baseline_coverage_summary.xlsx`

## Assumptions

- All crew are treated as interchangeable pilots (no rank, fleet rating, or pairing constraints).
- Duties require exactly 2 pilots when covered.
- Duty limits and rest limits come from `simulation/config.py` and are enforced by both optimizer constraints and post-run validation.
- Standby crew can be reserved from pre-assignment and then used for disruption recovery.
- Flight times are deterministic in the base schedule; stochastic effects come from delays and sickness processes.
- Delay generation is independent per flight event under configured probabilities.
- Delay propagation is connection-based within duty chains, with cancellations triggered by runtime checks.
- The simulation horizon is the generated 28-day schedule window.
- Outputs are workbook/table based; model state is persisted through Excel sheets rather than a database.
- Metrics summarize operational outcomes and robustness, not financial or passenger-demand impacts.

## Notes and Caveats

- `run_simulation.py` is the maintained entry point for this repository.
- `main.py` references `create_heuristic_roster`, which is not currently exported by `simulation/__init__.py`.
- `new_run_sweep.py` and `seed_data.py` contain hard-coded absolute workbook paths; update them to your local workspace path before running.
- Metrics are robust to empty-duty edge cases (no divide-by-zero on duty coverage).

## Typical Outputs To Inspect

- Console logs for `[DELAY]`, `[REPLACE]`, `[CANCEL]`, `[DUTY_OVERRUN]`, `[CURFEW]`
- Validation summary at end of run
- `crew_assignment_fact` sheet coverage quality in input workbook
- Final post-simulation workbook in `output/`
